# Build Brief: Agentic Engineering & Prompt Writing Quiz App

## 1. Your Role

Act as a senior frontend engineer, product designer, and agentic software engineering mentor.

Build a complete, functional, responsive quiz application that helps beginners test their understanding of basic agentic software engineering and prompt writing.

Work directly within the current project in Antigravity IDE. Before making changes, inspect the existing files and understand the project structure. If the project is empty, establish a simple structure appropriate for the requirements below.

Do not stop at a visual mockup. Deliver a working application with functional quiz logic, accurate scoring, responsive layouts, and tested user interactions.

## 2. Product Overview

**Working name:** Agentic Engineering 101

**Product description:** An interactive learning application that tests a learner's understanding of AI coding agents, effective prompt writing, project instructions, task planning, and software verification.

**Target audience:** Beginners learning to build software with AI coding agents.

**Primary objective:** Help learners assess their understanding of the concepts and learn from explanations provided after each answer.

**Core experience:**

Welcome → Start Quiz → Answer Questions → Review Results → Retry Quiz.

## 3. Technology Stack

Use only:

- HTML5
- CSS3
- Vanilla JavaScript

Technical constraints:

- Do not use React, Vue, or other frontend frameworks.
- Do not use a backend, database, authentication, or external AI APIs.
- Store quiz questions and answer data in a separate JavaScript data structure.
- Use readable, maintainable JavaScript with clear function names.
- Avoid unnecessary libraries and dependencies.
- Use semantic HTML and accessible interactive elements.
- Ensure the application works when served locally through a development server.
- Preserve useful existing project files and conventions rather than overwriting them unnecessarily.

Recommended project structure:

agentic-engineering-quiz/
  index.html
  style.css
  script.js
  README.md

You may adjust the structure if the existing project has an established convention.

## 4. Visual Design Direction

Create a polished, modern, light-theme educational interface with a soft pastel blue visual identity.

The interface should feel calm, intelligent, welcoming, and focused. It should look like a thoughtfully designed learning product rather than a generic quiz template.

### Colour palette

Use the following palette as the starting point:

- Main background: #EAF4FF
- Secondary background: #DCEBFA
- Card background: #F3F8FF
- Primary accent: #4A78C2
- Primary accent hover: #355FA5
- Main text: #24364B
- Secondary text: #65758B
- Borders: #CBDCF0
- Success: #287A59
- Error: #B54747
- Subtle blue tint: #E1EDFC

Important colour rules:

- Do not use pure white (#FFFFFF) as the page background.
- Do not use pure black (#000000) for text.
- Keep the interface entirely in light mode.
- Do not add a dark-mode toggle.
- Use pastel blue for the main visual identity without making every element the same shade.
- Use stronger blue accents for primary actions and important interactive states.
- Use green and red sparingly for answer feedback.
- Maintain readable contrast between text, backgrounds, borders, and controls.

Pure white may be used sparingly for tiny decorative details if absolutely necessary, but it must not dominate any surface. Prefer the specified tinted backgrounds throughout.

### Layout and composition

Design a centred quiz interface with a comfortable maximum content width of approximately 760px.

On desktop:
- Use generous spacing and a clear visual hierarchy.
- Position the brand or product name near the top.
- Keep the quiz content within a well-defined central container.
- Use a balanced composition with a progress indicator and clearly separated question content.
- Avoid unnecessary sidebars and dashboard widgets.

On mobile:
- Use a single-column layout.
- Provide comfortable touch targets.
- Keep the question and answer options readable without horizontal scrolling.
- Allow buttons to expand to the available width when appropriate.
- Prevent long question text from breaking the layout.

### Typography

Use a clean, modern sans-serif typeface.

Use a restrained typographic hierarchy:
- Small brand label or eyebrow text.
- Prominent page heading.
- Clearly readable question text.
- Consistent answer option text.
- Smaller, muted supporting information.

Use an available system font stack rather than adding a font dependency unless there is a compelling reason.

### Components

Create consistent styling for:

- Brand header
- Welcome section
- Quiz information summary
- Primary and secondary buttons
- Progress bar
- Question number indicator
- Question container
- Answer option cards
- Selected answer state
- Disabled button state
- Results summary
- Score display
- Answer review section
- Correct and incorrect feedback
- Restart action

Use subtle borders, modest corner radii, and restrained shadows where useful. Avoid excessive glassmorphism, gradients, floating decorations, and unnecessary animation.

Use simple CSS transitions for interactive feedback. Respect the user's reduced-motion preference.

## 5. Application Screens

### Screen A: Welcome

Display:

- Product name: Agentic Engineering 101
- Heading: Test Your Agentic Engineering Knowledge
- A concise description explaining that the quiz covers AI coding agents and prompt writing.
- Quiz details: 5 questions, beginner level, multiple choice.
- A prominent Start Quiz button.
- A small supporting note explaining that learners will receive explanations after completing the quiz.

Suggested introductory copy:

"How well do you understand the process of building software with AI coding agents? Answer five practical questions to test your knowledge of prompting, planning, and verification."

The Start Quiz button must initialise the quiz and navigate to the first question.

### Screen B: Question

Display:

- Current question number and total questions.
- A progress bar.
- The question text.
- Four selectable answer options.
- A primary action button.
- A secondary navigation action only if needed.

Interaction rules:

1. Display one question at a time.
2. Allow only one answer to be selected per question.
3. Visually distinguish the selected answer from unselected options.
4. Keep the Next Question button disabled until an answer is selected.
5. Once the learner selects Next Question, record the answer and move forward.
6. Prevent the same question from being scored more than once.
7. Update the progress indicator accurately.
8. Change the final navigation button label to "View Results" on the last question.
9. Prevent users from navigating beyond the first or last question.
10. Ensure the application cannot submit an answer twice through repeated clicks.

Do not reveal the correct answer immediately after selection. Show the answer explanations on the results and review screen after the quiz has been completed.

### Screen C: Results

Display:

- A clear completion message.
- The learner's score, such as 4 out of 5.
- The percentage score.
- The number of correct and incorrect answers.
- A short, encouraging summary based on the score.
- A detailed review of all five questions.
- A Restart Quiz button.

Use the following result categories:

- 0–39%: Keep Practising
- 40–79%: Good Progress
- 80–100%: Strong Understanding

Keep the language encouraging and informative. Do not make exaggerated claims about the learner's skill level.

For each reviewed question, display:
- The original question.
- The learner's selected answer.
- The correct answer.
- A concise explanation of the concept.

Clearly distinguish correct answers from incorrect answers using both text and visual styling. Do not rely on colour alone.

### Screen D: Restart

When the learner selects Restart Quiz:

- Reset the current question index.
- Clear all previously selected answers.
- Reset the score and progress.
- Clear previous results.
- Return to the welcome screen.

The learner must be able to complete the quiz again without refreshing the browser.

## 6. Quiz Content

Create five predefined, beginner-level questions.

Each question must contain:

- A unique ID.
- A question.
- Four answer options.
- The index or identifier of the correct answer.
- A concise explanation of the correct answer.
- A difficulty label if useful.

Use a separate JavaScript array of question objects.

### Question 1: Agentic Software Engineering

Question:

"What best describes agentic software engineering?"

Options:

A. Using AI only to explain programming concepts.

B. Using an AI agent to work toward a goal through planning, tool use, and iterative actions.

C. Generating an entire application from one sentence without review.

D. Replacing software testing with AI-generated code.

Correct answer: B.

Explanation:

"An AI coding agent can plan steps, use available tools, inspect results, and adjust its approach toward a defined goal. Its work still requires appropriate human oversight and verification."

### Question 2: Effective Prompt Writing

Question:

"Which prompt gives a coding agent the clearest implementation requirements?"

Options:

A. "Make me a quiz app."

B. "Build something impressive using JavaScript."

C. "Build a five-question quiz using vanilla JavaScript. Include answer selection, progress tracking, score calculation, restart functionality, and tests for the core interactions."

D. "Write as much code as possible and make it look modern."

Correct answer: C.

Explanation:

"A strong implementation prompt communicates the task, technology, required functionality, and expected verification. These details reduce ambiguity and make the result easier to evaluate."

### Question 3: Project Instruction Files

Question:

"What is the primary purpose of a project instruction file such as AGENTS.md?"

Options:

A. To store all the application's source code in one file.

B. To communicate project-specific instructions, conventions, and expectations to compatible coding agents.

C. To guarantee that every generated feature will be bug-free.

D. To replace the need for README documentation and software tests.

Correct answer: B.

Explanation:

"Project instruction files provide relevant guidance to coding agents. They can explain project conventions, development workflows, constraints, and expectations, but they do not guarantee correct implementation."

### Question 4: Planning Agentic Work

Question:

"You want an AI coding agent to add a quiz, a scoring system, and an answer review screen to an existing application. What is the most reliable approach?"

Options:

A. Ask the agent to change every file at once without a plan.

B. Focus only on the visual design and postpone the functionality indefinitely.

C. Break the work into manageable stages, define completion criteria, and verify important results as the agent progresses.

D. Allow the agent to make unrelated changes whenever it encounters a problem.

Correct answer: C.

Explanation:

"Breaking complex work into smaller, verifiable stages makes problems easier to isolate, reduces unnecessary changes, and helps keep implementation aligned with the intended outcome."

### Question 5: Testing AI-Generated Code

Question:

"An AI coding agent reports that the quiz app is complete. What should you do before considering the work finished?"

Options:

A. Trust the report and immediately publish the application.

B. Review the code changes, run relevant tests, and manually verify important user flows.

C. Assume that code without syntax errors cannot contain functional bugs.

D. Add more features before checking the existing implementation.

Correct answer: B.

Explanation:

"An agent's report is not proof that the implementation works. Reviewing changes, running tests, and checking real interactions provide evidence that the application meets its requirements."

### Content quality rules

- Verify that each question has exactly one correct answer.
- Keep incorrect options plausible but clearly incorrect.
- Avoid trick questions and unnecessarily technical language.
- Ensure explanations teach a reusable principle.
- Do not duplicate questions.
- Keep the question content separate from the rendering and scoring logic.

## 7. JavaScript Implementation Requirements

Implement the application using clear, beginner-readable JavaScript.

Organise the logic into small functions with specific responsibilities. For example:

- `startQuiz()` initialises a new session.
- `renderQuestion()` displays the current question.
- `selectAnswer()` records the learner's selection.
- `goToNextQuestion()` validates the selection and moves forward.
- `calculateResults()` calculates the final score and percentage.
- `renderResults()` displays the score and answer explanations.
- `restartQuiz()` resets the application.

These are suggested function names, not a requirement to create unnecessary abstractions.

Maintain a clear application state containing:

- Current question index.
- Selected answers.
- Quiz status.
- Final results when completed.

Calculate the final score from the recorded answers and the question data. Do not increment the score based on button clicks or allow the learner to earn multiple points from a single question.

Use event listeners and DOM manipulation appropriately.

Avoid using `eval()` or unnecessary dependencies.

## 8. Accessibility and Responsive Behaviour

Ensure that:

- All interactive controls can be operated using a keyboard.
- Answer options have clear accessible names.
- Keyboard focus is visible.
- Colour contrast is sufficient.
- Correct and incorrect states are communicated through text as well as colour.
- Buttons have appropriate disabled states.
- The interface works at narrow mobile widths.
- The layout does not overflow horizontally.
- Reduced-motion preferences are respected.
- Screen changes and results are communicated appropriately to assistive technologies.

Use semantic HTML elements and accessible patterns wherever practical.

## 9. Testing and Acceptance Criteria

Before declaring the project complete, verify all of the following:

### Core functionality

- The welcome screen appears on initial load.
- Start Quiz opens the first question.
- Exactly five questions can be completed.
- Every question has four answer options.
- Only one answer can be selected per question.
- The learner cannot continue without selecting an answer.
- The progress indicator reflects the current question.
- The correct answers produce the expected score.
- The final score and percentage are accurate.
- The results screen shows the correct answer for every question.
- Restarting resets the entire quiz state.

### Edge cases

- Repeated clicks do not double-count an answer.
- The last question does not lead to a nonexistent question.
- The learner cannot navigate past the end of the quiz.
- Restarting after completion does not retain previous answers.
- Empty or missing question data does not silently produce misleading results.

### Interface quality

- No pure white page background.
- The interface uses the specified light pastel blue palette.
- No dark theme or dark-mode toggle.
- Buttons, answer options, and feedback states are visually consistent.
- The layout remains usable on desktop and mobile.
- No horizontal overflow at common viewport widths.
- No browser console errors during normal use.

Run available checks and test the primary user flows in a browser. If automated tests are not configured, perform practical manual verification and document the checks completed. Never claim that a test passed unless it was actually run.
